# EventLink API Documentation
 
EventLink helps university students discover campus and club events, and lets organizers publish and manage them. This document describes the Assignment 2 prototype: a REST API with **mocked in-memory data**, token authentication and role-based access.
 
- Base URL: `http://127.0.0.1:8000/api/v1`
- Interactive docs (Swagger UI): `http://127.0.0.1:8000/docs`
- Mock data lives in memory and **resets every time the server restarts**.

## Authentication
 
There is no login in this prototype. Three fixed tokens are used instead. Send one in every events request:
 
```http
Authorization: Bearer user-a-token
```
 
| Role | Token | Permissions |
|---|---|---|
| Organizer A (regular user) | `user-a-token` | Reads, updates and deletes only their own events |
| Organizer B (regular user) | `user-b-token` | Reads, updates and deletes only their own events |
| Administrator | `admin-token` | Reads, updates and deletes any event |
 
- Missing or unknown token: `401 Unauthorized`.
- Valid token, but the event belongs to someone else: `403 Forbidden` (see [Design decisions](#design-decisions)).
- `GET /greeting` is public and needs no token.

## Response format
 
Every JSON response uses an envelope. The HTTP status always matches it: `2xx` means `success: true`, `4xx` and `5xx` mean `success: false`.
 
**Success**
 
```json
{
  "success": true,
  "message": "Event retrieved successfully.",
  "data": { "id": "evt_101", "title": "Introduction to Education Program of Faculty of International Resource Sciences Akita University, Japan" }
}
```
 
- `data` holds the resource, an array of resources, or `null` (after a delete).
- List responses add `meta`: `{ "total": 2, "page": 1, "perPage": 10 }`.
**Error**
 
```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "The request contains invalid or missing fields.",
    "details": [
      { "field": "title", "message": "String should have at least 3 characters" }
    ]
  }
}
```
 
- `error.code` is one of the fixed values below; clients use it to decide what to show.
- `details` appears only for validation errors.
- Messages never include stack traces, file paths or internal details.

## Error codes
 
| HTTP status | `error.code` | When it happens | How to fix it |
|---:|---|---|---|
| 400 | `VALIDATION_ERROR` | A field is missing, has the wrong type or length, or an unknown field was sent. Also invalid query parameters. | Read `error.details` and correct each listed field. |
| 401 | `UNAUTHORIZED` | The `Authorization` header is missing or the token is unknown. | Send `Authorization: Bearer <token>` with one of the three mock tokens. |
| 403 | `FORBIDDEN` | The event belongs to another user. | Use the owner's token, or `admin-token`. |
| 404 | `NOT_FOUND` | No event has this id, or the URL does not exist. | Check the id (list events first) and the URL. |
| 405 | `METHOD_NOT_ALLOWED` | The HTTP method is not supported on this URL. | Use one of the methods listed for the endpoint below. |
| 409 | `CONFLICT` | You already have an event with the same title, start time and location. | Change one of those fields, or edit the existing event. |
| 500 | `INTERNAL_ERROR` | Unexpected server error. | Retry; if it persists, report it. |

## The event resource
 
| Field | Type | Notes |
|---|---|---|
| `id` | string | Generated by the server, for example `evt_101`. Read-only. |
| `title` | string | Required. 3 to 100 characters. |
| `description` | array of strings | Optional, defaults to `[]`. At most 10 lines, each 1 to 500 characters. |
| `startsAt` | string | Required. ISO 8601 datetime with an offset, for example `2026-12-05T10:00:00+04:00`. Must be in the future when creating. |
| `registrationDeadline` | string or null | Optional. ISO 8601 datetime; must not be after `startsAt`. |
| `location` | string | Required. 2 to 100 characters. |
| `category` | string | Optional, defaults to `other`. One of `talk`, `festival`, `club`, `workshop`, `other`. |
| `capacity` | integer or null | Optional. At least 1. |
| `ownerId` | string | Set from the token when creating. Read-only; cannot be sent. |
| `isUpcoming` | boolean | Computed from `startsAt` on every response. Read-only; cannot be sent. |
 
Unknown fields in a request body are rejected with `400`.
 
## Endpoints
 
### List events
 
`GET /api/v1/events`
 
- **Headers:** `Authorization: Bearer <token>`
- **Roles:** organizers see only their own events; the administrator sees all.
- **Query parameters:**
| Name | Type | Default | Rules |
|---|---|---|---|
| `page` | integer | 1 | At least 1 |
| `perPage` | integer | 10 | 1 to 100 |
 
- **Success:** `200 OK`
- **Errors:** `400` (invalid `page` or `perPage`), `401`
**Example request**
 
```bash
curl "http://127.0.0.1:8000/api/v1/events?page=1&perPage=10" \
  -H "Authorization: Bearer user-a-token"
```
 
**Example response**
 
```json
{
  "success": true,
  "message": "Events retrieved successfully.",
  "data": [
    {
      "id": "evt_101",
        "title": "Introduction to Education Program of Faculty of International Resource Sciences Akita University, Japan",
        "description":  [
                            "Akita University’s Faculty of International Resource Sciences cultivates global specialists for overseas resource development and management. ",
                            "Integrating social sciences, humanities, natural sciences, and engineering, ",
                            "it offers three interdisciplinary programs: Resource Policy and Management, Earth Resource Sciences, and Earth Resource Engineering and Environmental Sciences. ",
                            "Key educational features include English-taught lectures from the second year and mandatory third-year overseas fieldwork, equipping students with advanced technologies and international policy discernment.",
                        ],
        "category": "adaSite-seminar",
        "location": "B-206",
        "startsAt": "2026-11-25T14:00:00+04:00",
        "endsAt": "2026-11-25T15:30:00+04:00",
        "capacity": 100,
        "registrationDeadline": null,
        "ownerId": "user-a",
        "isUpcoming": true
    }
  ],
  "meta": { "total": 2, "page": 1, "perPage": 10 }
}
```
 
### Get one event
 
`GET /api/v1/events/{id}`
 
- **Headers:** `Authorization: Bearer <token>`
- **Roles:** the owner or the administrator.
- **Path parameter:** `id`, the event id (for example `evt_101`).
- **Success:** `200 OK`, `data` is the event.
- **Errors:** `401`, `403`, `404`
**Example request**
 
```bash
curl http://127.0.0.1:8000/api/v1/events/evt_103 \
  -H "Authorization: Bearer user-a-token"
```
 
**Example response** (`403`, because `evt_103` belongs to user B)
 
```json
{
  "success": false,
  "error": {
    "code": "FORBIDDEN",
    "message": "You do not have permission to access this event."
  }
}
```
 
### Create an event
 
`POST /api/v1/events`
 
- **Headers:** `Authorization: Bearer <token>`, `Content-Type: application/json`
- **Roles:** any authenticated user. The owner is always the caller.
- **Body:** `title`, `startsAt`, `location` are required; the other fields are optional (see [The event resource](#the-event-resource)).
- **Validation rules:** field types and lengths as in the table; `startsAt` must be in the future; `registrationDeadline` must not be after `startsAt`; unknown fields are rejected; the same owner cannot have two events with the same title, `startsAt` and location.
- **Success:** `201 Created`, `data` is the new event.
- **Errors:** `400`, `401`, `409`
**Example request**
 
```bash
curl -X POST http://127.0.0.1:8000/api/v1/events \
  -H "Authorization: Bearer user-a-token" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Study Group Night",
    "description": ["Bring your laptop."],
    "startsAt": "2099-03-01T18:00:00+04:00",
    "location": "Library",
    "category": "workshop",
    "capacity": 25
  }'
```
 
**Example response** (`201 Created`)
 
```json
{
  "success": true,
  "message": "Event created successfully.",
  "data": {
    "id": "evt_106",
    "title": "Study Group Night",
    "description": ["Bring your laptop."],
    "startsAt": "2099-03-01T18:00:00+04:00",
    "registrationDeadline": null,
    "location": "Library",
    "category": "workshop",
    "capacity": 25,
    "ownerId": "user-a",
    "isUpcoming": true
  }
}
```
 
### Update an event
 
`PUT /api/v1/events/{id}`
 
- **Headers:** `Authorization: Bearer <token>`, `Content-Type: application/json`
- **Roles:** the owner or the administrator.
- **Path parameter:** `id`
- **Body:** the same fields as create. The event is replaced with the values sent, so optional fields you leave out go back to their defaults. `id` and `ownerId` never change.
- **Validation rules:** same as create, except `startsAt` may be in the past so that finished events can still be edited.
- **Success:** `200 OK`, `data` is the updated event.
- **Errors:** `400`, `401`, `403`, `404`
**Example request**
 
```bash
curl -X PUT http://127.0.0.1:8000/api/v1/events/evt_106 \
  -H "Authorization: Bearer user-a-token" \
  -H "Content-Type: application/json" \
  -d '{"title": "Study Group Night (updated)", "startsAt": "2099-03-01T18:00:00+04:00", "location": "Library"}'
```
 
**Example response** (`400`, empty title)
 
```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "The request contains invalid or missing fields.",
    "details": [
      { "field": "title", "message": "String should have at least 3 characters" }
    ]
  }
}
```
 
### Delete an event
 
`DELETE /api/v1/events/{id}`
 
- **Headers:** `Authorization: Bearer <token>`
- **Roles:** the owner or the administrator.
- **Path parameter:** `id`
- **Success:** `200 OK`, `data` is `null`.
- **Errors:** `401`, `403`, `404`
**Example request**
 
```bash
curl -X DELETE http://127.0.0.1:8000/api/v1/events/evt_106 \
  -H "Authorization: Bearer user-a-token"
```
 
**Example response**
 
```json
{
  "success": true,
  "message": "Event deleted successfully.",
  "data": null
}
```
 
### Greeting page
 
`GET /api/v1/greeting`
 
- **Headers:** none.
- **Success:** `200 OK`, an HTML page (`Content-Type: text/html; charset=utf-8`), not JSON. It shows the project, the team, every endpoint and the API status and version.
- Open `http://127.0.0.1:8000/api/v1/greeting` in a browser.

### Unsupported methods
 
Calling a URL with a method it does not support, for example `PATCH /api/v1/events/evt_101`, returns `405 METHOD_NOT_ALLOWED` in the error envelope.

| Id | Owner |
|---|---|
| `evt_101`, `evt_102` | ADA SITE (`user-a`) |
| `evt_103`, `evt_104` | ADA MUN Club (`user-b`) |
